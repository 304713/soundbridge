# 声桥 1.5.1

这一版没有新功能，三件事都是「把上次留下的尾巴收掉」。

## 托盘不再依赖 WinForms

托盘图标原来是借 WinForms 的 `NotifyIcon` 实现的——为了一个小图标，把整套 WinForms 拖进发布包。
现在改成直接调 `Shell_NotifyIcon`，右键菜单用原生弹出菜单。

中间试过 WPF 的 `ContextMenu`，做出来也能用，但实测**每多一个带 `HwndSource` 的窗口就要多吃 17～37 MB 私有内存**（每个窗口都带一整套渲染表面），比省下来的还多，所以放弃了。

实际收益（窗口打开、空闲、未连接同一台手机）：

| 指标 | 1.5.0 | 1.5.1 |
|---|---|---|
| 私有内存 | 72.1 MB | 64.9 MB |
| 工作集 | 154 MB | 135 MB |
| 加载模块 | 163 | 155 |
| 压缩包 | 67.7 MB | 60.4 MB |

托盘在资源管理器重启后会自动挂回去（监听 `TaskbarCreated`），这条以前是 WinForms 替我做的，现在自己实现。

## 日志改成异步批量写

以前每条日志都是「打开 → 写入 → 关闭」三次系统调用，而且发生在 UI 线程上。机械硬盘上一次 5～20 毫秒，
连接失败重试时一秒钟十几条，界面就会一顿一顿的。

现在是丢进队列、后台线程每秒合并落盘一次，退出前同步刷完。日志文件保持可读状态，
你点「日志」时不必先退出程序。

顺带把枚举设备的日志收敛了：筛选器那行只记一次，候选数量变了才记。以前没设备时每 3 秒一行，
挂一晚上就是几万行。

## 切换默认播放设备失败时，给出办法

切换默认设备用的是系统未公开的 `IPolicyConfig` 接口，Windows 大版本更新后有失效的风险。
以前一旦失效，表现是「连上了、显示已连接，但声音还在扬声器上」，界面上只有一句「切换失败」。

现在：

- 切完会**回头确认**系统默认设备真的变了。接口返回成功不算数——签名对不上时它照样返回 0。
- 接口整个不可用时（类还在、接口对不上），本次运行内不再重试，也不再刷日志。
- 失败原因翻成人话：「那台设备已经不在了」「设备失效了，重新插一下或重连蓝牙」。
- 说明文字旁边会出现「去手动选 →」，直接打开系统的声音设置。

## 修掉的问题

- **没勾「关闭时缩到托盘」时，关窗口后进程还在托盘里**，再点「打开主界面」会因为窗口已经关闭而报错。
  现在这种情况下关窗口就是退出。
- 界面上写死的版本号（一直显示 `v1.5.0`）改成从程序集读取，不会再和实际版本对不上。
- 源码注释和文档里出现过真实的蓝牙地址前缀，换成占位符。
